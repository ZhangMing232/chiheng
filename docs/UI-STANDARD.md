# 赤轨 UI 设计标准 v1（唯一权威 · 2026-10-10 定稿）

> 动因学 deepseek-harness-quant 的 `UI_STANDARD.md`：「把设计定死成标准，不然越来
> 越差，甚至得完全推倒重做」。本文档把赤轨**现有**约定固化下来——不是发明新规范，
> 是把已经在代码里的取舍写成条文，新页面照此施工，改动前必读。
>
> 三铁律：①UI 是壳，数据是 API　②空态说人话，绝不留白　③枚举/文案只写一处

## 1. 设计令牌（语义类名，禁止裸色值）

赤轨用 Tailwind 语义 token（`text-muted`、`bg-surface`、`border-line`、`text-warn`、
`text-fg`）。规矩：

- 新代码**只用语义类名**，禁止写死的 `text-gray-500` / `#xxxxxx`（图表 canvas
  等没法用类名的场合除外，且要在注释里说明为什么）。
- 语义 token 的增改在 Tailwind 配置层做，一次改动全站生效；不许在页面里
  「临时」引入新色值然后留下来。

**★红涨绿跌是 A 股铁律**：收益为正 → 红，为负 → 绿。禁止美式红跌绿涨。
检查方法：搜 `#C0392B|#0F6E56` 或直接看渲染，拿不准就问。

## 2. 布局

- **首屏 ≤1 屏**：主结论数字放大放前面（因子页的「N 个里 M 个」是范本）。
- **低频内容一律折叠**：`<details>` 或 `collapsible.tsx`，默认收起——第一眼
  清爽，功能不丢。用户明确点过「要折叠」的诉求不许回退。
- Tab 子页面只渲染选中那个区块，七个全挂 DOM 的老做法已废（factors.tsx）。

## 3. 组件

| 组件 | 规范 |
|---|---|
| 空态 | `StateBlock`：「没有数据」必须同时给**为什么 + 怎么补**（重跑命令/开关位置）。禁止空白页、禁止空集合冒充「0」。 |
| 徽标/强调 | 过关 ✅ / 淘汰 ❌ / 衰减 ⚠️ 用 emoji + 语义色，全站一致。 |
| 数字 | 大数字用 `clamp()` 流式（`clamp(28px, 4vw, 42px)` 范本）；表格数字右对齐。 |
| 表格 | 判据原话直接显示（「\|t\|=4.35 vs 临界 3.09」），不许只给 ✓/✗ 不说依据。 |
| 区块 | `Section`（title + hint）：hint 写「这区块是什么 + 数据从哪来」，不写字面重复 title 的话。 |

## 4. 文案纪律

- **同一句话只写一处**：六关图例（GATE_LEGEND）、可交易闸文案、披露口径，
  都由 lib 层出，页面只消费——发现两处文案说的是同一件事，抽成一个来源。
- **缺数据的样子就是缺**：`pass: null` 渲染「—」，禁止补成 ✗ 更禁止补成 ✓
  （factors-view.ts 的铁律，测试钉着）。
- 判据、出处、命令（可复制的）写全：引用回测数字必须带 baseline 文件名。

## 5. 数据契约

- 页面数据全部走 server function / 本地产物文件，**前端不藏业务常量**。
- server function 读不到数据要带回 `why`（data-status.ts 的 `Notice` 三问：
  为什么 / 影响 / 什么时候恢复），页面照实说，不许静默吞。
- data/ 不在 git 里：换机器必然读不到，空态文案里要自带重跑命令。

## 6. 改动纪律

改本文档 = 改全站契约。新增组件/新 token 先进文档再进代码；推翻旧条目
要在条目下留「作废于 + 原因」，不许悄悄删。
