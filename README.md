# 赤轨

A 股选股。六套策略分开记账，每套每天最多 10 只。名额按天算，昨天进的那批就算还没卖出，也不占今天的名额。现价打到买入价才记入，打到卖出价或止损价再卖。买入当天不能卖。已经持有的那只不再重复买——不分哪套策略买的，手上有了就不再开第二笔。收盘（15:00）之后不再记新仓；收盘后才补记的那天不进胜率和累计收益的统计。

这不是投资建议，也不会下单。上涨占比在样本记满之前只是样本。

次日补涨在 14:30 冻结当天最强的三个概念板块里的次强。那之前标的是预估价，不是买入价。

## 代码怎么读

从这几个文件看就够，上面都有白话注释：

| 文件 | 内容 |
|---|---|
| `src/lib/market/types.ts` | 名词表。现价、涨跌幅、市值各是什么单位 |
| `src/lib/market/strategies.ts` | 六套策略怎么算买入价、卖出价、止损价 |
| `src/lib/market/rules.ts` | 启动前期的门槛 |
| `src/lib/market/journal-book.ts` | T+1、涨跌停卖不掉、手续费 |
| `src/lib/market/session.ts` | 现在是早盘、午休还是尾盘 |
| `src/routes/` | 每个页面。选股、资金、消息、个股 |
| `scripts/record-journal.ts` | 后台记账。只写本机账，不下单 |

登录、脚手架、预览相关的文件开头写了「日常选股不用改这里」。

## 回测：结论和怎么用

无前视回测，只用在 t 日收盘时已知的信息，t+1 日才成交。跑法：

```bash
node --experimental-strip-types --import ./scripts/alias.mjs scripts/backtest.ts   # 常规
BT_FACTOR=1 BT_N=10 node ...          # 因子检验：某个指标到底有没有预测力
BT_SWEEP=1 node ...                   # 止损幅度扫描
BT_HALF=first|second node ...         # 前后半段分别跑
BT_OFFSET=1 node ...                  # 换一批互不重叠的股票再跑一遍
```

看结果之前先记住两件事，否则会自己骗自己：

1. **「平均收益」不是阿尔法。** 表里同时给出「同期全池」——同一时间、抽样池全体等权持有的收益。
   两者相减才是选股挑出来的那部分。放量突破平均 +0.41%，同期全池 +0.19%，超额 +0.22%（t=0.59），
   远低于 t=2，也就是没测出来。它赚的主要是这批活跃票本身的贝塔。
2. **t 值不到 2 就等于没测出来。** 单笔波动很大，几百笔的均值也能是运气。
3. **前后两段翻号的更不能用。** 全区间 t 高不代表整段有效，得看 `BT_HALF=first/second` 同不同号。

> **所有数字的出处**：`data/backtest/baseline-2026-10-06.txt`。那里记了完整的开关组合、
> 样本区间（2025-09-18 ~ 2026-09-30，抽样 300 只）和复现命令。**引用任何回测数字都要带上它，
> 不然没法判断是在哪个配置下测的。**

因子检验里唯一站得住的是 **60 日涨幅（反向）**，也就是「跌得多的后面弹得快」：
10 天超额 +0.63% / +0.30% / +0.22% / -0.16% / -0.38%（t=-2.81，五档单调），
前半段 t=-3.80、后半段 t=-1.68，换一批不重叠的股票仍是 +1.02%（t=4.91）。
5 日涨幅在两段里直接翻号（-2.35 / +1.11），那种不能用。

按这个做成第六套「中期反转」：按现价买 60 日跌得最惨的 10 只，拿满 10 个交易日。
**不放常规止损：限价单口径的回测里 -8% 止损的超额是 -0.02%（t=-0.13），不设止损是 +1.03%（t=5.06）
——止损把那批高波动票的反弹整齐地切在了前夜。**（补跑发现：按现价买口径下止损几乎不触发，
所以 -25% 现在只是一根保险丝，不是验证过的参数。）

### ⚠ 回测和线上不是同一个口径，补跑之后（2026-10-06）

上面那些数字是**限价单口径**（买价挂昨收 +3%、高开超 3% 不追）跑出来的，
而线上 `strategies.ts` 的 `reboundOrder` 是**按现价买、不挂单、`hit` 恒为 true**。
补跑加了 `BT_BUYMODE=spot` 开关，线上口径自己的数字是：

| 区间 | 笔数 | 胜率 | 超额 | t |
|---|---|---|---|---|
| 全区间 2025-09 ~ 2026-09 | 2398 | 51% | **+0.55%** | 3.10 |
| 前半段 2025-09 ~ 2026-03 | 1239 | 57% | +1.15% | 5.35 |
| 后半段 2026-03 ~ 2026-09 | 1159 | 44% | **−0.10%** | −0.34 |
| 换一批股票（`BT_OFFSET=1`） | 2399 | 50% | +0.53% | 3.06 |

好消息：**按现价买没有毁掉这个信号**（+0.55%，仍过 t≥2）。「按现价买」是有意的决定
（实测挂单价买要亏 2.90%），补跑只是补上它自己的数字。

### ⚠ 中期反转还没通过段一致性检验

**两种完全不同的买法，在同一段时间都失效**：

| | 前半段 | 后半段 |
|---|---|---|
| 限价单（+3% 挂单） | +1.36% (t=6.73) | −0.16% (t=−0.57) |
| 按现价买（无条件） | +1.15% (t=5.35) | −0.10% (t=−0.34) |

一个会追高不买、一个全买，后半段都是负的，t 都在 −0.3~−0.6——意思是**和 0 区分不开**，
不是「亏了」。**后半段没有效应。** 换一批股票仍然成立，所以**问题在时段，不在票**。

这排除了「策略细节没调好」这个解释：**是环境变了。**
所以「唯一测出阿尔法的一套」这个说法要收回——它通过了量级（t=3.10）和跨样本（+0.53%）
检验，但没通过时段一致性。

**不要为了让两段同号去调参数。** 那是过拟合的入口，而且会毁掉一个还没被证伪的信号。
正确做法是等实盘样本：中期反转第一批结算在 2026-10-22，实验台会自己给结论。

已知风险：这套买的是连续下跌的票，退市和 ST 风险明显高于别的策略。
`tradable` 已经挡掉 ST、4 元以下、40 亿以下和贴着涨跌停的，但回测的股票池里没有已退市的票，
这部分风险在回测数字里是看不见的，真实结果会比上面的数差。

## 怎么启动（这台机器上唯一可靠的方式）

```bash
cd /Volumes/colorful/chiheng
npm run serve          # 前台跑，窗口别关，关了就停
```

看到 `赤轨在本机 0.0.0.0:8787 上提供访问` 就是起来了，然后浏览器开 http://127.0.0.1:8787
（局域网里用这台电脑的 IP 加端口）。终端窗口要一直开着——**这不是缺点，是故意的**：
前台跑的时候所有输出都打在屏幕上，服务起不来会立刻看到红字，而不是悄悄躺在那里。

想让登录后自动起来，在**你自己的终端**里跑一次：

```bash
cd /Volumes/colorful/chiheng && npm run install:mac
```

`launchctl` 只认本人终端发起的调用，从别的工具里发起的会被系统拒绝
（`Bootstrap failed: 5: Input/output error`），所以这一步必须你自己跑。

**不要依赖双击桌面的「赤轨.app」。** 这台机器上它不可靠：双击走 Finder，
没有终端，出错时什么都看不见，表现为「点了没反应」。它现在会把过程写进
`data/app-launch.log`、出错弹系统对话框（比早前好），但既然终端这条路已经够用，
日常就用终端。真要用 app，出问题先看 `cat data/app-launch.log`。

## 预警微信推送（PushPlus）

记账进程发现新预警（到止损价 / 到卖出价 / 到期该卖）时，除了 Mac 通知还会推一条微信。
token 放在 `data/push-config.json`（已被 git 忽略，不会进代码库）：

```json
{ "token": "你的 PushPlus token" }
```

在 [PushPlus 官网](http://www.pushplus.plus) 扫码登录就能拿到 token。
界面入口：顶栏铃铛下拉里直接粘贴保存（只有主人账号看得到这块）；留空点保存是关闭推送。
也可以直接编辑 `data/push-config.json`，效果一样。不填就静默跳过，
只发 Mac 通知——推送失败永远不会影响记账本身。页面上的铃铛红点 / Toast 不受影响。

## 部署到 Mac mini

需要 Node.js 22，以及 Mac 自带的「终端」。交易日电脑要开着、联网，至少从 9:30 到 15:00。系统设置里把接通电源时的睡眠关掉。14:30 不能休眠，否则补涨按开机后第一次看到的名单冻结。

账本在 `data/books/`，只在这台电脑上，不会进 Git。更新代码不会删账。

每天的状态只有两种：`locked` 是当天第一批信号在收盘（15:00）封盘后才记的，`provisional` 是盘中记的。`provisional` 之后不会变成 `locked`，这不是结算丢失，是标注信号时点；持仓的卖出盯盘不受这个标签影响，照样自动成交。

**项目放在外置硬盘上也可以，但要额外做一步。** macOS 的隐私保护不让 launchd 进可移动磁盘
（会报 `getcwd: Operation not permitted`、退出码 78），所以自启配置里不能写 `WorkingDirectory`，
改由 `scripts/start-mac.sh` 自己进目录；`npm run install:mac` 已经按这个要求生成配置了。

### 第一次

1. 打开「终端」。
2. 没有 Node 时，用浏览器打开 https://nodejs.org ，安装 22，装完关掉终端再开一次。
3. 没有 git 时，执行 `xcode-select --install`，弹窗里点安装，装完再开一次终端。
4. 取代码并构建（路径换成你自己的，别带空格）：

```bash
cd /Volumes/colorful        # 本机放在外置硬盘上；放用户目录就用 cd ~
git clone https://github.com/ZhangMing232/chiheng.git
cd chiheng
npm install && npm run build:mac
```

5. 装上登录自启。**这一步必须自己在「终端」里执行**，从别的工具间接发起的会话没有注册
   登录服务的权限，会连报三次 `Bootstrap failed: 5: Input/output error`：

```bash
npm run install:mac
```

6. 浏览器打开 http://127.0.0.1:8787 。装好之后每次登录会自己起来；服务进程万一没了，
   常驻的 `home-server.mjs` 会在几秒内把它拉回来（连续失败则退避到一分钟一次）。

### 以后我推了新代码

终端里（路径换成你自己的）：

```bash
cd /Volumes/colorful/chiheng
npm run mac:update
```

它会拉取 `main`、安装依赖、构建、再装上登录自启。拉不下来时，把 `git status` 的整段输出发回来，不要自己改代码。

> 外置硬盘上重新打包这一步没法由辅助工具代劳：项目在 `/Volumes` 下时，
> `npm run build:mac` 拷贝静态资源会失败（`CODEBUDDY_BROKER_DENY`），
> 得自己在终端里跑。记账那套逻辑不走打包产物，改完立刻生效，不受影响。

### 平时管理

| 命令 | 作用 |
|---|---|
| `npm run mac:status` | 当前版本、服务开没开、页面能不能开 |
| `npm run mac:log` | 最近日志，出错时把这段发回来 |
| `npm run mac:restart` | 只重启，不重新构建 |
| `npm run mac:stop` | 停止。登录后也不会再开，直到 start |
| `npm run mac:start` | 再启动 |

桌面图标：`npm run app:mac`，桌面会有「赤轨.app」。双击只开窗口，关掉窗口不会停止记账。

只想先手动看一眼：`npm run serve`。开发用 `npm run dev`（http://127.0.0.1:8080），不会自动记账。

每个人一本账，文件是 `data/books/用户id.json`。收盘后按用户复制到本机 `chiheng-backup`。现在没有打开注册，这台 Mac 用的是 `dev-user`。原来的 `data/journal.json` 会在第一次记账时复制过去，之后不再改它。以后若开放注册，新用户从加入当天另记一本，不会继承已有成交。行情仍然只拉一份。策略和偏好仍是全站共用，不随用户改。打到买入价、止损价或卖出价时，账本自动成交，同时弹一条通知。通知只是提醒，成交记在本机账上，不会发到券商。到期该卖也会自动记一笔，并提醒一次。资金页只供复盘，不改变买入条件。选股页抬头写着上次记账时间，超过 3 分钟没有更新会标成记账中断。
