## 3. 本次修复的两处（都有实测证据）

### 修复 A：判决层补第三道关（超额必须为正）

**事故实证**：
```
data/strategy-genome.json 里的 fused_vol_confirmed_momentum
  status: promoted          ← 被标成「站住」
  clusteredT: -2.85         ← 信噪比过线（|t|≥2）
  excessPp: -1.24           ← 超额 -1.24pp（稳定跑输）
  halvesSameSign: true
  reason: "聚类 t=-2.85 过线且方向稳定（超额 -1.24pp，2352 笔）"
                            ↑ 理由文字自己都写着超额为负
```

**根因**：`judgeGenomeVerdict` 只卡 `|t|≥2` 和前后同向。`|t|` 只回答「稳不稳」，
不回答「赢没赢」。稳定亏损的策略其负向 t 同样过 `|t|≥2`。

**危害**：这条错误结论会被下一轮 AI 当既成事实读进去（passedFactors /
近亲封禁 / 融合种子），**整个反思机制在错误地基上迭代**。

**修复**（`genome-verdict.ts`）：
- 新增第三道关：`excessPp` 必须 > 0
- `excessPp` 为 null → `testing`（不知道赢没赢就不许站住）
- 超额为负 → `rejected`，理由写明「稳定跑输 / 反向信号」，与页面 P1-3 的
  「反向·不可用」文案口径一致
- 历史数据已按新规则重判：`fused_vol_confirmed_momentum` 从 promoted → rejected
- 测试：3 条新增（负超额判死、超额为 0、超额 null），并改写了一条**断言旧 bug
  行为**的测试（原「负信噪比 → promoted」）

### 修复 B：新建规则改动效果回验

**新增** `src/lib/market/rule-change-effect.ts`：
- `evaluateRuleChangeEffect`（纯函数）：对比改动前后两段窗口的逐笔收益
- 判据：观察期 ≥10 交易日 + 前后各 ≥30 笔 + 差值超过 ±0.3pp 噪声区
- 结论四态：`pending` / `inconclusive` / `effective` / `ineffective`
- `ineffective` 时给 `revertAdvice`（**只建议，不自动回滚**——回滚要人拍板）
- 挂到 `record-journal.ts` 收盘段，每天一次，结果落 `data/rule-change-effects.jsonl`

**首版判据的自我纠错**（值得记）：
初版设 MIN_DAYS_AFTER=5、样本各 ≥10 笔，实测立刻抓到自己犯错——
切在 11-05 时改前 247 笔、改后仅 53 笔，却判出「+6.87pp effective」。
那不是规则有效，是**改后样本又少又短**（22 个交易日总共 300 笔）。
收紧到 10 交易日 + 各 30 笔后，**全部判 pending** —— 这才是诚实的结论。

## 4. 用户视角：产品精简空间

### 4.1 22 个纯重定向壳（占 48 个路由的 46%）

`index / rotation / reports / decision / sectors / signals / screener / positions /
notes / ladder / grid / seats / inbox / overview / brief / calendar / intel /
debate / hotmoney / review.flow ...`

**判断**：这些是历史包袱，但**不是垃圾**——它们保住了书签不断链（11-11 以来
反复整合页面的必然产物）。**不建议删**，删了书签全断。

**建议**：维持现状，但**别再新增**。真正的问题是它们污染了路由清单的阅读体验。

### 4.2 页面数与实际使用价值

48 个路由里，22 个是壳，26 个是真实页面。但**真正每天打开的**大约是：
`/today`（今天干什么）、`/strategies/positions`（我的仓）、`/watch`（盯盘）、
`/huiyan`（自证）、`/strategies/screener`（选股）、`/settings`。

剩下 20 个页面（`/cycle` `/factors` `/backtest` `/research/*` `/studio`
`/butler` `/overseas` `/themes` `/youzi` `/flow` `/news` `/interval` `/rs`
`/my-stocks` `/membership` `/admin` `/ai` `/symbol` ...）是**低频但不可删**。

**判断**：赤轨的问题不是「页面太多」，是**同一件事在多个页面各说一遍**。
11-11 的整合已经收了一轮（策略 5→3、因子 6→1、资金 8→4），方向对。

### 4.3 真正该精简的（按收益排序）

| 优先级 | 项 | 依据 |
|---|---|---|
| P0 | **别再新增页面** | 22/48 已是壳，新增只会加壳 |
| P1 | 侧栏 53 条目 → 按「每天用 / 每周用 / 备用」分层 | 现在五组+系统，53 条一屏放不下要滚 |
| P2 | `/factors` 六个 tab 是否真有人挨个看 | 低频页里 tab 最多的 |
| P3 | 22 个重定向壳合并成一张表驱动 | 现在 22 个文件，每个 20 行 |

### 4.4 一个必须说的问题：**同一件事被算两遍的隐患还在**

P2 对账只解决了 `/today` vs 账本。但还有几处：
- `strategy-verdicts.json`（回测聚类判决）vs `data/books`（实盘账本）
  —— 前者说全部无 alpha，后者说 value +5%。**两个真相并存**。
- `/backtest` 页的回测数字 vs `/huiyan` 的落档战绩 —— 口径不同但用户容易混

**建议**：不是合并，而是**在页面上显式标注「这是回测口径 / 这是实盘口径」**，
跟已经做好的「理论成交 vs 真实成交」同款处理。

## 5. 整体视角：三个系统性问题

### 5.1 策略层已经死了，但系统还在假装它在研究

- `strategy-verdicts.json`（11-13 15:46）：11 套策略 clusterT **全部为负**
  （最好 spring +1.02，最差 rev3 −1.88），excess 全部为负
- 我今晚跑的 baseline（11-13）：11 套全未过两关，超额全在 ±0.8% 内
- 但系统每天还在跑因子挖掘、基因组融合、挑战者提名
- **判断**：这不是 bug，是**设计如此**——「没有 alpha 就继续找」是对的。
  但**缺少一个「找多久该停」的判断**。现在等于无限期空转，烧 API 额度。

### 5.2 实盘账本与回测判决完全背离

| 来源 | value 表现 |
|---|---|
| 回测（250 日 / 297 只） | 未过两关，超额 ≈ 0 |
| 实盘账本（26 笔已平） | **+0.18%/笔，累计 +5%** |

**判断**：26 笔太少，+5% 大概率是运气。但**这个背离本身值得监控**——
如果继续积累还保持正收益，说明回测口径漏了什么（比如实盘选的是「当前市场
存在的东西」，回测是历史抽样）。**建议加一个「实盘 vs 回测背离」监控项**。

### 5.3 规则优化器在同一个参数上来回摆

`earlyRejectDays`：15→3→5→10→12→20→30（6 次）
`earlyRejectGap`：0.05→6→0.05→0.08（4 次）

**判断**：这是**没有效果反馈**的必然症状——每次改动都基于当时诊断，
但诊断不知道上次改了什么、效果如何。修好回验后，这条应该会自愈
（系统会看到「上次改无效」并建议回滚）。

**但要提醒**：回验目前全 pending（账本只有 22 天）。**至少还要 10 个交易日
才能看到第一批结论。**
