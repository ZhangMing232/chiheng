## 3. 本次修复的两处（都有实测证据）

### 修复 A：判决层补第三道关（超额必须为正）

**事故实证**：
```
data/strategy-genome.json 里的 fused_vol_confirmed_momentum
  status: promoted          ← 被标成「站住」
  clusteredT: -2.85         ← 信噪比过线（|t|≥2）
  excessPp: -1.24           ← 超额 -1.24pp（稳定跑输）
  halvesSameSign: true
  reason: "聚类 t=-2.85 过线且方向稳定（超额 -1.24pp，2352 笔）"
                            ↑ 理由文字自己都写着超额为负
```

**根因**：`judgeGenomeVerdict` 只卡 `|t|≥2` 和前后同向。`|t|` 只回答「稳不稳」，
不回答「赢没赢」。稳定亏损的策略其负向 t 同样过 `|t|≥2`。

**危害**：这条错误结论会被下一轮 AI 当既成事实读进去（passedFactors /
近亲封禁 / 融合种子），**整个反思机制在错误地基上迭代**。

**修复**（`genome-verdict.ts`）：
- 新增第三道关：`excessPp` 必须 > 0
- `excessPp` 为 null → `testing`（不知道赢没赢就不许站住）
- 超额为负 → `rejected`，理由写明「稳定跑输 / 反向信号」，与页面 P1-3 的
  「反向·不可用」文案口径一致
- 历史数据已按新规则重判：`fused_vol_confirmed_momentum` 从 promoted → rejected
- 测试：3 条新增（负超额判死、超额为 0、超额 null），并改写了一条**断言旧 bug
  行为**的测试（原「负信噪比 → promoted」）

### 修复 B：新建规则改动效果回验

**新增** `src/lib/market/rule-change-effect.ts`：
- `evaluateRuleChangeEffect`（纯函数）：对比改动前后两段窗口的逐笔收益
- 判据：观察期 ≥10 交易日 + 前后各 ≥30 笔 + 差值超过 ±0.3pp 噪声区
- 结论四态：`pending` / `inconclusive` / `effective` / `ineffective`
- `ineffective` 时给 `revertAdvice`（**只建议，不自动回滚**——回滚要人拍板）
- 挂到 `record-journal.ts` 收盘段，每天一次，结果落 `data/rule-change-effects.jsonl`

**首版判据的自我纠错**（值得记）：
初版设 MIN_DAYS_AFTER=5、样本各 ≥10 笔，实测立刻抓到自己犯错——
切在 11-05 时改前 247 笔、改后仅 53 笔，却判出「+6.87pp effective」。
那不是规则有效，是**改后样本又少又短**（22 个交易日总共 300 笔）。
收紧到 10 交易日 + 各 30 笔后，**全部判 pending** —— 这才是诚实的结论。

存在的东西」，回测是历史抽样）。**建议加一个「实盘 vs 回测背离」监控项**。

**但要提醒**：回验目前全 pending（账本只有 22 天）。**至少还要 10 个交易日

## 8. 用户视角：真实使用场景推导（2026-11-14 补）

### 8.1 一个交易日里，用户真实会做什么

从自动化日志与数据落盘时间反推（`data/history/*` 全部在 15:12 更新）：

```
09:15  竞价开始 → 三池开始采集（每 3 分钟）
09:20  推送「明天买什么」（前瞻 3 只）
09:26  竞价审核 → reviewed.json 落盘 → 推送买入单
09:30  开盘，按价挂单
15:00  收盘
15:12  收盘封印：涨停池/K线落档 → 回溯打分 → 日报推送
15:15  算明天：题材热度/监管雷达/轮动
15:46  自动判决写入 strategy-verdicts.json
15:5x  AI 自动进化（若当天还没跑）
23:30  全量快照备份
```

**用户在这个流程里真正需要的只有 4 个时刻**：
1. **早上 09:20 收到推送** → 知道今天买什么
2. **09:26 后再看一眼** → 确认名单没变
3. **盘中偶尔瞄一眼** → 持仓有没有到止损/目标
4. **收盘后看日报** → 今天怎么样

**结论**：`/today` 是唯一的核心页。其他 18 条侧栏入口都是**辅助查询**。

### 8.4 一个真实场景的完整链条（验证设计是否自洽）

**场景：某天 value 策略连续 3 笔止损**

```

   record-journal 收盘结算 → 3 笔 exit=stop → 账本记录

② 分析原因
   loss-attrib.attributeTradeLoss → 按退出原因分类（止损/到期/目标）
```

**这条链现在闭合了。** 之前断在第⑤环。

**但有一个诚实提醒**：链条闭合 ≠ 策略会变好。当前 11 套策略全部无 alpha，
链条能做的只是「更快发现问题、更快回滚错误改动」，不能凭空创造 alpha。
**这是设计边界，不是缺陷。**

## 9. 第 2 轮补充审计（2026-11-14 凌晨）

### 9.1 🔴 重大发现：现役唯一策略默认不进回测判决

**实证**：`data/strategy-verdicts.json` 里有 11 套策略（trend/breakout/early/
reversal/rev2/rev3/bk2/bk3/bk4/rebound/spring）——**没有 `value`**。

查 `scripts/backtest.ts:1630`：
```ts
...(process.env.BT_VALUE === "1"
  ? { value: { label: "低估值·回测变体", fn: valueBacktest, hold: holdOf("value") } }
  : {}),
```
**value 必须手动加 `BT_VALUE=1` 才注册**。注释写的理由是「免得日常基线报告多一行、
也免得污染页面读的 JSONL」——但代价是：**现役唯一策略长期没有默认判决数据**。

**危害**：`ACTIVE_STYLES=["value"]` 在真实跑，reconcile 每天在记它的成交，
但「这套策略到底有没有 alpha」这个问题，系统默认状态下答不出来。
所有「11 套全部无 alpha」的结论都不包含正在用的那一套。

**补跑 result（2026-11-14 01:0x，BT_VALUE=1）**：

| 策略 | 笔数 | 胜率 | 均值 | 同期全池 | 超额 | 信噪比 | 判定 |
|---|---:|---:|---:|---:|---:|---:|---|
| **低估值·回测变体** | 2131 | **45%** | -0.41% | -0.55% | **+0.14%** | **1.16** | 两道关：+0.54 / 前后翻脸 ✗ |

**这是全部 12 套里胜率最高（45%）、超额最高（+0.14%）、信噪比最高（1.16）的一套**
——但仍然没过 `|t|≥2`。结论：**现役策略是"矮子里的将军"，不是有 alpha**。

**建议**：把 `BT_VALUE` 默认打开（或至少让每日判决包含它）。代价是多一行报告，

**实际数据**（逐笔核对 `data/books/dev-user.json`）：

|---|---|---:|---:|---:|
| value-stop10 | 11-04 | 8 | 1 | 7 |

11-13 卫星化学/南京银行），完全符合「每天限 1 只」的预登记铁律。**根本没有买不到的问题。**

**所以**：11.3 的三方案（A/B/C）**撤回**，挑战者机制不需要动。

```
                ——因子本身没有区分度或表达式有问题，不是「差一点」，换方向
```

### 15.4 AI 现在能读到的死因摘要（实测）

`necropsyLines()` 输出 21 行，开头是聚合统计：
```
死因档案共 85 条：「单调+显著+两段+换样本+多重检验」×46、「显著+两段+换样本+多重检验」×13…
按类别：动量×23、量能×21、形态×16、规模×12、反转×8、波动率×5。
「单调也挂」说明信号形状不对或太弱，别再提同形状的微调变体。
```
后面每条带：名称、类别、败在哪几关、表达式、**当初的经济逻辑**。

**这才是「给出解决办法」链条该有的输入**——AI 现在能看出
「动量类死了 23 个、其中 46 个死于五关全挂」，从而知道该换方向而不是继续微调。

### 15.5 这是用户要的「反思机制」的供给侧

用户的原话：「知道亏损 → 思考为什么亏损 → 找出亏损原因 → 给出解决办法」。
前七轮修的是**判决与验证**（下游），这轮修的是**原因供给**（上游）——
如果 AI 看到的死因全是同一句废话，它再聪明也只能瞎猜。

**「改了代码」和「改到了 AI 的输入」是两件事。**

第 8 轮我改对了逻辑、加了测试、回填了数据、测试全绿——但那条信息

## 18. 第 11 轮：体检 8 项分层展示（面板高度降 42%）

### 18.1 做了什么

上轮论证「8 项该分层但不该砍」，这轮落地。

`HealthRow` 加 `cadence` 字段（`daily` / `weekly` / `ondemand`），页面按它分三组：

| 组 | 内容 | 展示 |
|---|---|---|
| **需要处理** | 任何 `state=bad` 的项 | 置顶常驻（红底） |
| **每天看** | 记账心跳、策略闸、AI 闭环 | 常驻 |
| **每周看 / 出问题才看** | 自动进化、规则回验、实盘vs回测、探索效率、判决功效 | 折叠（点击展开） |

**实测效果**：
- 面板高度 **427px → 249px（降 42%）**
- 默认可见「每天看 · 3」
- 折叠 5 项，点开可看全部 8 项，**无遗漏**

### 18.2 关键纪律：bad 项强制置顶

**「出问题才看」不等于出问题时能藏起来。**

如果一个 `state=bad` 的项（比如记账心跳停了）因为 cadence 是 `ondemand`
被折叠进「出问题才看」，那等于把最该看到的东西藏了。
所以分组逻辑第一条就是：**先按 state 筛 bad，再按 cadence 分剩下的**。

守门测试专门钉住这条：
```
bad 项必须置顶，哪怕它的 cadence 是 ondemand
→ 实盘vs回测（bad, ondemand）必须出现在第一组，且不再出现在折叠组
```

### 18.3 实现过程中的一个小插曲

给 `cadence` 设成**必填**后，TypeScript 一次性报出 9 处遗漏。
这比「可选字段 + 默认值」更安全——可选字段会让「忘了填」静默通过，
必填则编译期就把所有漏项怼出来。**宁可编译期红，不要运行时悄悄错。**

最终 14 处赋值（8 项 × 各有分支路径）。

### 18.4 面板现在长这样

```
需要处理 · N        ← 只有出现 bad 才有，红底置顶
每天看 · 3          ← 记账心跳 / 策略闸 / AI 闭环
▸ 每周看 / 出问题才看 · 5 项（点开）
```

## 21. 第 14 轮：方案 C 落地——家族级方向学习（用户拍板「按你的建议来」）

### 21.1 设计定位（不越权）

**不替换**单变体判决——`judgeChallenger` 的 promote/reject 仍是最终转正关卡
（AI-BOUNDARY.md 的判决口径没动）。

方案 C 的定位是**方向学习**：用池化样本回答「哪类参数调整整体好/坏」，
结论只喂给 AI 提下一轮的方向。**只读账本，不写盘、不自动改任何东西。**

### 21.2 实现

新增 `src/lib/market/direction-learn.ts`（+7 测）：

- 变体笔按「参数维度 × 档位」分组（stopPct=8 一组、holdDays=12 一组…）
- 每组均值 vs 冠军侧均值 → 超额
- 门槛：变体侧 ≥8 笔、冠军侧 ≥10 笔、超额超 ±1pp 才给方向

**为什么池化能绕开功效墙**：3 个止损=8 的变体各 4 笔（单变体 4 笔判不出），
池化后止损=8 家族有 12 笔——同一方向的证据合并，检出能力大幅提升。

### 21.3 真实数据首跑（2026-11-14 账本）

```
变体 42 笔 / 冠军 25 笔 / enoughData=true

持有天数=8 的变体（13 笔）相对冠军超额 +7.02pp——这个方向整体比冠军好
持有天数=12 的变体（7 笔）相对冠军超额 +5.10pp——值得往这个方向再提
```

**这是系统第一次给出「方向感」**——单变体判决做了 17 天只产出 1 笔已平仓，
而方向学习用同样的账本直接学出了「持有天数往长调是好的」。

### 21.4 接入三处

| 位置 | 作用 |
|---|---|
| `strategy-ai.ts` ctx + prompt | AI 提下一轮时有方向依据：「优先往整体比冠军好的方向提；标了跑输的，除非有新证据否则别碰」 |
| `/settings` 系统体检第 9 项 | 管理者可见当前学到的方向 |
| `directionAdvice=null` | 数据不够时**不渲染方向段**——AI 看不到就不猜 |

### 21.5 与判决功效的关系

判决功效警告（R5）说的是「单挑框架判不出」，家族方向（R14）给出的是
「绕开单挑框架之后能学到什么」。两者互补：

- **判决功效**：警告不要等一个不会来的单变体判决
- **家族方向**：给出当下就能用的方向信号

**结果**：AI 的输入从「12 笔判决还没有结果（等）」变成
「持有天数=8 方向 +7pp（现在就往这提）」——反思闭环从「堵漏」进入「供能」。

`strategy-ai.ts` 的功效提示里写死了「标准差约 10%」「≥11.5pp」——**这是我第 7 轮自己写进去的**。账本继续攒，标准差会变；这正是第 7 轮扫掉「30 笔」硬编码时总结过的教训，同一双手差点再犯一次。

修法：`ctx.tradeSd`（从真实账本现算）+ `minDetectableEffectPp()`（R5 已有的公式）动态渲染。实测：
```
⚠️ 判决功效有限：单笔收益标准差约 10.1%，每侧 12 笔只能检出 ≥11.5pp 的差异…
```
`tradeSd=null`（账本 <30 笔）时整段不渲染——没有可靠数字就不提醒。

**教训**：硬编码不是一次性清扫能解决的，**每往 prompt/页面里加一个数字，都要问「这个数下个月还对吗」**。
