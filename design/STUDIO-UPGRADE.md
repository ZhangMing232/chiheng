## 一、改造的四个层次（从底到顶，每层独立上线）

```
L1 渲染架构  ← 一次投资，长期受益：版式从"手画"变"组合"
L2 信息密度  ← 不依赖拍板，当天能上：单图从 1 模块到 6-9 模块
L3 组图叙事  ← 抖音/小红书成套：从一张图到一组图
L4 品牌工程  ← 配置化 + 按需生成 + 合规细节
```

## L1 · 渲染架构（核心投资）

**问题**：现在 4 种版式都是 canvas 手画坐标，改一次版式伤一次；
字段没值时只能显示占位文案，做不到“卡片级隐藏”。

**三条路线**（调研结论，事实在 BENCHMARK §3）：

| 路线 | 版式能力 | 依赖 | arm64 风险 |
|---|---|---|---|
| a. 继续 canvas | 手算坐标，改版痛苦 | 零 | 无 |
| b. SVG 模板 + resvg | 声明式，接近 CSS 的 flex/圆角/渐变；条件渲染就是模板里一个 if | `@resvg/resvg-js` 或 satori | **要先探**（纯 Rust/Native 二进制，akshare 有前科） |
| c. HTML 模板 + 无头浏览器 | CSS 全能力（daily_stock_analysis 走的这条） | chromium + CJK 字体 | 最高（它官方 Docker 都要专门装字体） |

**我的建议：b（SVG+resvg）**，理由：版式能力比 canvas 高一个量级，
又不需要无头浏览器那套字体/运维负担。**但先探再定**——探的方法就一条：
`npm i @resvg/resvg-js` 装完画一张带中文的图，装不上或中文变方框就退回 a。

**落地方式**：新建 `studio-card.ts`（StudioSpec → SVG 模板 → resvg → PNG），
canvas 实现保留做回退，双轨跑一段。ranking 版式先迁（用得最多），
稳了再迁 event/stat/ladder。

**验收**：同一 spec 两条路线产出视觉一致；中文正常；resvg 路线支持
“字段没值不渲染该卡片”。

## L2 · 单图信息密度（不依赖任何拍板，建议最先做）

调研事实：daily_stock_analysis 的卡 6-9 个模块、开盘啦是模块拼盘、
条数纪律是每类最多 2-3 条。现在我们的图一个模块一条列表。

**各版式加什么**：

| 版式 | 现在 | 加什么 |
|---|---|---|
| 榜单（ranking） | top N 排名列表 | ① 头部一行 AI 结论（标题就是）② 分布条：前 3 占比 vs 其余 ③ 同源 mini 榜（个股图带板块归属、板块图带领涨股）④ 涨/跌家数一行小字 |
| 复盘（stat） | 指数卡+分布条 | ① 板块领涨/领跌各 top3（它的纪律：各 3 条）② 资金观察一句（AI 从数据提炼，不编净流入）③ 涨跌停计数已有 |
| 游资 | 席位排名 | ① 头部“最猛席位+它的票”结论行 ② 每个席位带的票从 3 只改 2 只（条数纪律） |
| 事件 | 标题+摘要 | ① “接下来看什么”一句（AI 给，只从摘要里的信息推）② 涉及票带涨跌幅 |
| 梯队 | 横条 | ① 已有情绪脚注 ② 加炸板率一个数（/signals 现成数据） |

**条数纪律（抄它的）**：每类信息最多 2-3 条，逼排序不堆砌——这既是设计
也是防“公式化”：10 条平铺是报表，3 条是观点。

**诚实填充（抄它的，和赤轨纪律同源）**：字段没值不渲染该卡片/该行，
不留空框不写“暂无”——数据缺就说缺哪个。

**验收**：每种版式信息模块 ≥4；每条数据能指回数据源；空数据不出空框。

## L3 · 组图叙事（抖音/小红书成套）

调研事实：小红书爆款是“封面大字报 + 组图叙事（痛点→过程→结果）”，
封面 = 标题放大+高对比+一个最炸的数字；daily_stock_analysis 是单卡
（它的场景是推送，我们是发帖，场景不同）。

**一次生成一组（3-4 张）**：

| 位 | 内容 | 版式 |
|---|---|---|
| 封面 | AI 标题（10-18 字）+ 全场最炸的一个数字 + 日期 | 大字报（新） |
| 全景 | 指数/分布/家数——今天什么成色 | stat |
| 结构 | 榜单/梯队/游资（用户选的体裁数据） | ranking/ladder |
| 观点 | AI 的一段观点 + 互动引导（“你觉得明天……”） | 文字卡（新） |

**平台成套**：抖音 9:16 / 小红书 3:4 / 公众号 16:9——同一内容三套尺寸，
不是缩放（版式随尺寸重排：竖版一列、横版两列）。

**验收**：一次生成 3-4 张一组，打包下载（zip）；三平台各一套。

## L4 · 品牌与工程细节

| 项 | 内容 | 出处 |
|---|---|---|
| 品牌配置化 | 水印文案、二维码占位图、账号名——写进 /settings，图片底部显示 | daily_stock_analysis 的 ShareImageBranding |
| 按需生成+缓存 | 批量预生成浪费；生成一次缓存，改数据才失效 | 同上（它点击分享才渲染） |
| 元数据清理 | PNG 剥 EXIF（resvg 产物本来干净；canvas 走 toBlob 也干净——记一笔防回归） | jpeg.top 合规清单 |
| 合规三件套 | 每张图固定：风险提示条 + 数据截至时间 + “不构成投资建议” | 全行业标配，我们已有，组图后每张都要有 |
| 分享即生成 | 图只在用户点“生成”时产，不进日常推送链路（推送走文案） | daily_stock_analysis 的按需模式 |

## 二、体裁扩充（回答“财经图文还有什么”）

新体裁的边际成本 = 一个数据源函数 + 一段文案指令 + 一个版式组合。
以下按“数据现成度”排（都基于项目已有数据）：

| 候选体裁 | 数据源 | 现成度 |
|---|---|---|
| 涨/跌幅榜 | universe-cache 快照 | ✅ 现成（screener 就在用） |
| 昨日涨停今日表现（接力验证） | 涨停池 + 行情快照对拍 | ✅ 现成，打板圈刚需 |
| 新股日历 | 已接的 ipo（events） | ✅ 现成 |
| 持仓收益分享图 | 账本（TurtleTrace 的爆款功能） | ✅ 现成，注意隐私打码 |
| 自选股日报 | 自选 + 行情 | ✅ 现成 |
| 盘口异动（炸板/地天板） | 涨停池 broken | ✅ 现成 |
| 两融/北向 | margin + flow.north | ✅ 现成 |

**我的建议**：先做“昨日涨停今日表现”和“持仓收益分享图”——前者是打板
内容的刚需（Vibe-astock 有专门功能），后者是每个用户都能发的自发内容
（裂变素材）。**做不做、先做哪个你定。**

## 四、落地顺序（建议）

```
第 1 步：L2 信息密度        —— 不依赖拍板，现有 canvas 上直接加模块，当天能上
第 2 步：L1 探路（resvg）   —— 半小时出结论；通则 ranking 版式试点迁移
第 3 步：L3 组图            —— 依赖 L1 的模板体系（或 canvas 多画两张，先上简化版）
第 4 步：L4 品牌工程        —— 随时可做，建议和第 3 步并行
体裁扩充：L2/L3 稳定后，按第二节的现成度挑
```

每步验收标准写在对应小节里。每步独立 commit，回滚不影响其他层。
