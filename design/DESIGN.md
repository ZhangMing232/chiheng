## 1. 目标用户与使用场景

### 1.1 用户画像（基于真实数据，不是想象的）

设计之前先核了实际数据：

| 事实 | 值 | 来源 |
|---|---|---|
| 使用者数量 | **1 人**（只有一本账） | `data/books/dev-user.json` |
| 账本规模 | 2 个交易日 / **71 笔**（已卖 11 · 在拿 60） | 同上 |
| 策略分布 | 低估值 20 · 趋势回踩 17 · 启动前期 16 · 放量突破 13 · 次日补涨 5 | 同上 |
| 行情规模 | 每分钟一次全市场 **5221 只**快照 | 代码 |
| 页面数量 | 6 个 | `src/routes/` |
| 图标使用 | lucide-react 已装，**全项目仅用 3 个** | 代码 |

**结论：这是单用户、单机的专业工具，不是产品。** 所有决策从「一个人盯一天盘」出发，不从「服务多少用户」出发。

**用户特征**

- **专业但不是机构**：模拟盘，每笔按满仓记，不记仓位大小
- **长时间盯盘**：盘中 4 小时 + 盘后复盘，眼睛疲劳是真实问题
- **对口径极其敏感**：反复追问「有没有阿尔法」「跑赢指数没」
- **会自己排查**：出问题翻日志、看终端，不接受「玄学问题」

### 1.2 三个核心场景

#### 场景 A · 盘中盯盘（9:25–15:00，每 60 秒一轮）

**行为**：扫指数带 → 看持仓有没有到止损/目标价 → 看精选有没有到买入价。

**约束**：一屏要能看到足够多行（60 秒一轮，滚动是打断）；状态变化要能被余光捕捉（涨跌用色块）；**盘中界面禁止非必要动画**。

#### 场景 B · 发现信号 → 建仓 → 跟踪 → 结算（跨天）

**行为**：切策略看精选 → 记代码 → 等打到买入价 → 每天看持仓 → 到 10 个交易日卖出。

**约束**：**「等」是核心状态**，所以「等待买入 / 已到买入价 / T+1 / 持有 / 止损」必须一眼可辨；历史要能回溯（按交易日分组，因为「我那天买了什么」是高频查询）。

#### 场景 C · 盘后复盘

**行为**：看这批策略跑出来多少、跑赢指数没、哪套在亏。

**约束**：数字要能横向比较（用统计条）；口径要写在旁边（「名义金额」「已扣费」不能藏页脚）。

### 1.3 硬约束

| 约束 | 来源 | 设计后果 |
|---|---|---|
| 红涨绿跌 | A 股约定 | 不可配置、不可反转 |
| 深色为默认 | 盘中 4 小时 | 深色是主方案，浅色次要 |
| 高密度 | 60 秒一轮 | 行高 32px，一屏 12+ 行 |
| 单用户单机 | 只有一本账 | 不做多租户、不做权限矩阵 |
| **状态必须诚实** | 见下 | 见 §1.4 |

### 1.4 这个产品最重要的一条原则：状态诚实

**这不是通用原则，是被现实教出来的。** 2026-10-05 一天出现三次「页面在说谎」：

| 页面显示 | 真实原因 | 用户代价 |
|---|---|---|
| 「这套策略现在没有符合的股票」 | 主源降级，新浪源缺字段 | 查了 3 小时日志 |
| 「当前持有 0 只」「累计收益 —」 | 服务端账本读不到 | 以为数据丢了 |
| 页面无任何样式 | 跑的是旧进程，`/assets/` 全 404 | 以为 CSS 坏了 |

**共同结构：把「我拿不到」说成「没有」。**

**对策（已落地）**

1. **徽标只说结论，点开答三问**：为什么 / 影响什么 / 什么时候恢复
2. **拿不到 ≠ 没有**：`null` 一律显示「—」，绝不用 `0` 顶替
3. **部分失败要显式**：某天有一笔持仓拿不到现价，那天浮动盈亏显示「—」，不按能算的那几笔凑数
4. **每次降级留日志**：`getServerJournal` 的 catch 打一行 `[journal]`

> 这条要写进代码评审清单。**页面好看但说谎，比页面丑更糟。**

## 2. 信息架构与核心页面

### 2.1 页面职责

| 路由 | 名称 | 唯一职责 | 频率 |
|---|---|---|---|
| `/` | 选股 | **回答「今天买什么」** | 每 60 秒 |
| `/positions` | 持仓 | **回答「我拿着什么、赚了多少」** | 每 60 秒 |
| `/news` | 消息 | **回答「什么在影响我的票」** | 手动 |
| `/symbol` | 个股 | **回答「这一只为什么涨/跌」** | 按需 |
| `/flow` | 资金 | **回答「钱从哪来、到哪去」** | 手动 |

**每个页面只回答一个问题**——这是判断页面是否该存在的唯一标准。

### 2.2 导航模型

**一级导航 5 项，顶栏横排**：`选股 · 持仓 · 消息 · 个股 · 资金`

**为什么持仓独立成页**：原来看板在选股页第三屏以下，盯盘时够不着。现在它是第二个标签——从「今天买什么」到「我拿着什么」是一次点击。

**为什么没有「设置」**：字号和深浅色在顶栏右侧。这是本地个人偏好，不该占一级导航。

### 2.3 数据流

```
              ┌──────────────┐
              │ 行情快照      │ 5221 只 · 3 分钟缓存
              │（单一数据源） │
              └──────┬───────┘
     ┌────────────────┼────────────────┐
     ↓                ↓                ↓
┌────────┐      ┌──────────┐     ┌────────┐
│ 选股    │      │ 持仓      │     │ 资金    │
└────┬───┘      └────┬─────┘     └────────┘
     │ 点击名称       │ 点击代码
     └────────┬───────┘
              ↓
      ┌──────────────┐
      │ 个股详情      │
      └──────────────┘

  ┌────────┐  独立拉快讯，标出与持仓/精选重合的票
  │ 消息    │
  └────────┘
```

**关键约束：行情快照是单一数据源。** 选股/持仓/资金读同一份快照（3 分钟缓存），所以**三个页面的数字永远一致**——不会出现「选股页显示跌 2%，持仓页显示涨 1%」。

## 3. 关键交互流程

### 3.1 盘中循环（最高频，每 60 秒）

```
① 看指数带（6 格横排，色块涨跌）        5 秒
        ↓
② 看持仓：谁到止损/目标价了              20 秒
        ↓
③ 看精选：谁到买入价了                  20 秒
        ↓
④ 要不要换策略？                       10 秒
        ↓ 命中
   点名称 → 个股详情
```

**要点**：①②③ 必须在一屏内，不滚动不切页。

⚠️ **待改进**：持仓区目前按建仓日排序，应改为**按紧急度排序**（止损/目标价命中的排最前，其余按收益率）。盘中第②步是最高频动作，排序应该服务于它。

### 3.2 建仓到结算

```
选中 ──► 等到买入价 ──► 记一笔 ──► T+1 ──► 持有 ──► 到目标/止损 ──► 卖出
          │                       │                          │
          │                       └─ 当天不能卖                └─ 跌停卖不出→顺延
          ├─ 涨停买不进
          └─ 不追（已离买入价太远）
```

**六个中间态必须一眼可辨**

| 状态 | 视觉 |
|---|---|
| 等待买入 | 中性灰药丸 |
| 已到买入价 | 品牌色药丸 |
| 涨停买不进 / 不追 | 警示色药丸 |
| T+1 | 中性灰药丸 |
| 持有 | 中性灰药丸 |
| 止损 / 卖出 | 跌绿 / 涨红药丸 |

**已落地**：`Tag` 组件 + `limitTag` / `planExit`。

### 3.3 异常处理流程（这个产品特有）

```
      数据源降级 / 账本读不到 / 构建过期
                     ↓
        顶部出现琥珀色徽标「降级？」（只占两个字，不遮挡内容）
                     │ 点击
                     ↓
    ┌────────────────────────────────┐
    │ 为什么    主源没拉下来，换到新浪  │
    │ 影响      突破和中期反转今天不出票 │
    │ 什么时候   主源恢复后自动切回      │
    │           [重新拉一次] [知道了]   │
    └────────────────────────────────┘
```

**为什么浮层不用横幅**：横幅把内容往下推，盘中等于打断。浮层只在主动点击时出现。

**已落地**：`noticeOf()` / `accountNotice()` + `StatusPill`。

**规则**

1. **颜色只表达涨跌和状态，不表达好坏**
2. **品牌色只用在两处**：顶部 2px 品牌条、焦点环。正文区几乎全是中性灰——**颜色是稀缺资源**
3. **涨跌三重编码**：色块 + 正负号 + 数字
4. **警告色是琥珀不是红**——红在这个项目里已经是「涨」

**核验方法**（要核**两路**）

```python
def lin(c): c/=255; return c/12.92 if c<=0.03928 else ((c+0.055)/1.055)**2.4
def L(h): h=h.lstrip('#'); r,g,b=(int(h[i:i+2],16) for i in (0,2,4))
         return 0.2126*lin(r)+0.7152*lin(g)+0.0722*lin(b)
def ratio(a,b): la,lb=L(a),L(b); return (max(la,lb)+0.05)/(min(la,lb)+0.05)
```

> 必须同时核「文字 vs 底色」和「**文字 vs 色块**」。2026-10-05 之前只核了第一路，
> 漏了色块——tinted 底拉低对比度，深色涨红在色块上只有 4.38:1。

### 5.2 三态统一规则

**最容易做散的地方**——每个页面自己写一句话，凑不到一块儿。定死：

#### 加载态

**用骨架屏，不用 spinner。** spinner 只说「在转」，骨架屏还暗示了「下面是列表」。

- 骨架行高等于真实行高，**布局不跳**
- **超过 1 秒才显示**，否则闪一下反而干扰
- **永远说清在拉什么**：「正在拉行情」优于「加载中」

#### 空态

**空有四种，一种说法**：

| 类型 | 标题 | 补充 |
|---|---|---|
| 从来没有过 | 「还没有开过仓」 | 怎么会有第一笔 |
| 有但今天没有 | 「今天这套没有符合条件的票」 | 门槛是多少、可刷新确认 |
| 被筛选掉了 | 「没有符合筛选条件的」 | 当前条件 + 清除入口 |
| **拿不到** | 「不是选不出票，是行情源缺字段」 | 缺什么、什么时候恢复 |

> **第四种是今天新增的，也是最重要的一种。**「拿不到」和「没有」必须用不同文案——§1.4 的直接落地。

规则：标题说结论、补充说原因 + 下一步；**永远给一个可执行的下一步**；不用「暂无数据」这种零信息量文案。

#### 错误态

- **说清影响范围**：「上面显示的是上一次的」比「加载失败」有用一百倍
- **给恢复动作**：能重试就给按钮
- **不弹浏览器原生 `alert()`**
- **服务端同时记日志**——页面说清了，服务端也要留线索

### 5.3 微交互

| 交互 | 参数 | 说明 |
|---|---|---|
| 按钮悬停 | `scale(1.05)` + 边框变色，200ms `cubic-bezier(.2,.8,.2,1)` | |
| 按钮按下 | `scale(.97)` | 触觉反馈 |
| 表格行悬停 | **只变背景 180ms，不缩放** | 密集表格里缩放会晕 |
| 进度条 | 宽度 300ms | 让「名额涨了」看得见 |
| 浮层 | 淡入 + 上移 3px，200ms | |
| 骨架屏 | 1.4s 呼吸 | |
| **数字变化** | **不做动画** | 盘中一切动效都是干扰 |

全部包在 `@media (prefers-reduced-motion: no-preference)` 里。

## 6. 响应式适配策略

### 6.1 断点（只有这 4 个）

**移动优先**：基准样式面向 320px，向上渐进增强。

| 断点 | 行为 |
|---|---|
| **320px+** | 单列。导航横滚。**表格降级成卡片流**。可点元素 44×44 |
| **576px+** | 利好/利空两栏并排。统计条每行 2 个 |
| **768px+** | **表格模式**：表头 sticky、首列 sticky，隐藏字段回来。页签收到 6px |
| **992px+** | 面板内边距 12→16px |
| **1200px+** | 内容居中限宽 1360px |

### 6.2 表格降级（关键一策）

**问题**：6~8 列在 375px 上横向滚，等于**一只股票都看不全**。

**方案**：不是缩字号，是**换呈现方式**。

```
≥768px                              <768px
┌────┬────┬────┬────┐               ┌─────────────────┐
│名称│现价│涨幅│买入│               │ 中洲控股 000042  │
├────┼────┼────┼────┤               │ ─────────────── │
│中洲│8.46│+1.9│8.53│               │ 现价      8.46  │
│控股│    │ %   │   │               │ 涨跌幅   +1.93% │
└────┴────┴────┴────┘               │ 买入      8.53  │
                                    └─────────────────┘
```

```css
@media (max-width: 767px) {
  .data-table thead { display: none }
  .data-table tbody tr { display: grid; grid-template-columns: repeat(3, 1fr); gap: 6px 10px; padding: 12px }
  .data-table tbody td { display: block; text-align: left; white-space: normal }
  .data-table tbody td::before { content: attr(data-l); display: block; font-size: 10px; color: var(--color-muted) }
  .data-table tbody td[data-opt] { display: none }
}
@media (min-width: 768px) { .data-table tbody td[data-opt] { display: table-cell } }
```

- `data-l` 是字段名，**只在窄屏出现**（桌面有表头不重复）
- `data-opt` 标次要列（卖出价/卖出止损/策略），窄屏先藏
- 首格独占一行并压分隔线

### 6.3 免媒体查询的网格

```css
.stats { display: grid; grid-template-columns: repeat(auto-fit, minmax(140px, 1fr)); }
```

容器多宽自动排多少列，加减格子不用改 CSS。

### 8.3 两条硬性提醒

**① 改 `styles.css` 后必须 build + 重启，两步都不能少**

```bash
# 终端 1
npm run serve
# 终端 2（另开窗口）
npm run build:mac
# 浏览器
Cmd + Shift + R
```

`.output` 的静态资源清单是**进程启动时读进内存**的。构建换新产物后磁盘文件名带新哈希、内存里还是旧的 → `/assets/` 下**每一个** 404 → 页面渲染出内容但一点样式都没有。服务启动时会自动警告，但别依赖它。

**② 中文文件里核对改动不要用 grep**

`grep` 匹配中文字符串会**静默返回空**（明明有 9 处却打印 0）。用 python 读文件核对。

## 9. 设计决策 ↔ UX 原则对照

| 决策 | 原则 | 体现 |
|---|---|---|
| 涨跌用色块不用字色 | 视觉搜索：颜色比文字快 | 余光扫过就分出红绿 |
| 状态用浮层不用横幅 | 不打断：盘中位移即干扰 | 点击才出现 |
| 表格降级成卡片 | 信息完整 > 版面紧凑 | 375px 宁可多占行也看不全不行 |
| 「拿不到」与「没有」分开 | **状态诚实** | 两种文案、两种视觉 |
| `null` 显示「—」不用 0 | **状态诚实** | 0 是断言，— 是「不知道」 |
| 字重只两档 | 密集信息可读性 | 半粗体让数字糊成一片 |
| 层次靠边框不靠阴影 | 暗色界面对比 | 阴影让密集数字发灰 |
| 品牌色只用两处 | 视觉显著性稀缺 | 正文区全中性灰 |
| 持仓独立成页 | 任务频率决定层级 | 盘中第二高频操作 |
| 数字用等宽 | 纵向可比 | 小数点成列 |
| 动效克制 | 专注力 | 盘中禁止非必要动画 |
| 触摸目标 44px | 移动端可达性 | 手指点不准就没用 |
| 每个页面只答一个问题 | 单一职责 | 判断页面去留的唯一标准 |

### 8.4 v4 的配色体检：抓到三个踩线的

把两套主题的 14 组前景/背景组合全算了一遍（WCAG 相对亮度公式），发现三处不到 4.5:1：

| 色 | 原来 | 问题 | 现在 |
|---|---|---|---|
| 浅色 `muted` | `#667084` | 放在 `surface-2` 上只有 **4.40**（灰标签会踩线） | `#5e6779` → 5.02 |
| 浅色 `brand` | `#d8261c` | 放在 `surface-2` 4.40、放在 `brand-soft` 上 **4.36** | `#c62016` → 5.12 / 5.07 |
| 深色 `brand` | `#e35d55` | 放在 `surface-2` **4.33**、`brand-soft` 上 **4.28** | `#e8665e` → 4.71 / 4.66 |

改完两套主题最低 **4.66**，全部过 AA。这三个数字后续改色值时要重算，
`design/system.html` 的色板里标的就是这套结果——别凭眼睛判断够不够。

### 8.4b 原型和产品之间的一处刻意差异

`app.html` 里结论区的巨号字是 `clamp(40px, 7vw, 68px)`——原型里它独占一屏，可以这么放。
产品里首屏下面还压着筛选栏和精选表，同样 68px 会把它们挤到第三屏去，
所以 `lab-panel.tsx` 收到 `clamp(32px, 5vw, 52px)`：冲击感还在，但首屏装得下。

这类差异要认：原型是「如果这一屏只做一件事」的样子，产品是「五件事抢一屏」的样子。
照抄原型数字通常会翻车。
