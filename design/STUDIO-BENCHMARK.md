## 二、它们怎么设计（产品/交互层）

### 1. daily_stock_analysis：三件套输入，仪表盘输出

- **输入极简**：自选股代码 + 一个 LLM key + 一个推送 webhook。没了。
- **输出是「决策仪表盘」不是数据罗列**：综合评分（0-100）、动作标签
  （强烈买入/观望/卖出）、核心结论一句话、作战计划（理想买点/止损/目标）、
  技术参考、催化与风险（各最多 2 条）、下一步观察（行动窗口+检查时间）。
- **分享是二次动作**：用户点"分享"才生成图（按需生成+缓存），不是每次报告都出图。
- **可追问**：/chat 问股页，15 种策略视角（均线/缠论/事件驱动……），
  带实时 K 线接着答。
- **多渠道同源**：企微/飞书/Telegram/邮箱，哪些渠道转图可配
  （`MARKDOWN_TO_IMAGE_CHANNELS`），转换失败**回退纯文本**。

### 2. 开盘啦「一图复盘」：模块化拼盘，一张图看全市场

盘面梳理（时间轴）+ 涨停梯队 + 龙虎榜席位 + 亏钱效应 + 板块核心。
**形态是"多模块卡片拼盘"，不是一条排名列表**——每块自己一个小标题，
块与块之间视觉分隔。

### 3. 小红书方法论（稿定/运营文）：封面大字报 + 组图叙事

- 封面 = 大字报（标题放大+高对比+痛点/悬念），内页每段 ≤3 行、
  留白 30%、黑白+1 主题色、emoji 每 2-3 段一个不超 5 个
- **组图顺序有叙事**：「痛点→过程→结果」或「全景→细节→对比」
- 3:4 竖版（1080×1440）是小红书信息流展示面积最大的尺寸
- 风险提示条、互动引导（"评论区见"）是标配组件

### 4. TurtleTrace：一键分享图解决"手动截屏拼图"的痛

收益曲线+持仓统计一键成图。启发：**用户要的是"不用动手"，
不是"更多参数"**。

## 三、它们怎么工作（技术架构层）

### 核心事实：主流是「HTML 模板 + 无头浏览器截图」，不是 canvas 直画

daily_stock_analysis 的链路（docs/share-images.md 原文）：

```
结构化 JSON（to_dict）+ 稳定 Markdown
  → share_image 模块（优先读 JSON，Markdown 兼容回退）
  → 个股决策卡 / 市场复盘卡 HTML 模板
  → wkhtmltoimage / markdown-to-file / Playwright 三引擎选一
  → 1080px 长图 PNG
```

**为什么都走 HTML**（我的判断）：CSS 的 flex/grid、圆角、阴影、渐变、
字体排版是现成的，一天能出一个新版式；canvas 手画全要自己实现，
改一次版式伤一次。且 HTML 模板能**条件渲染**——字段为 N/A 的卡片自动隐藏，
不会出现空框。

三条渲染路线对比（给赤轨选型用）：

| 路线 | 代表 | 优点 | 代价 |
|---|---|---|---|
| canvas 直画 | **赤轨现状** | 零依赖、纯客户端 | 版式靠手算坐标；改版式痛苦；条件渲染难写 |
| HTML + 无头浏览器 | daily_stock_analysis | CSS 全部能力；模板易维护 | 服务端要 chromium/wkhtmltopdf + CJK 字体（它的踩坑记录：缺字体中文会消失） |
| SVG 模板 + resvg | pydreamplet 教程、jpeg.top | 声明式（比 canvas 强）、纯 Node/Rust 无浏览器 | Flex 布局子集（Satori）或手写 SVG；生态较小 |

### 其他工程细节（值得抄）

- **按需生成+缓存**：点击"分享"才渲染，不是每次报告都渲染
- **品牌配置化**：小红书二维码/昵称/URL 都是 env 配置，Data URI 内嵌不依赖网络
- **颜色语义持久化**：模板持久化生成时的 green_up/red_up 语义（换市场不改色）
- **转换失败回退文本**：图挂了不影响推送主链路
- **元数据清理**：exiftool 剥 EXIF/GPS（jpeg.top 的合规清单）
- **CJK 字体是硬依赖**：官方 Docker 内置 Noto CJK，缺字体会让中文从 PNG 里消失

## 四、成品长什么样（内容结构层）

### daily_stock_analysis 的个股卡字段映射（它文档里的原表）

| 图区 | 内容 | 条数纪律 |
|---|---|---|
| 头部 | 名称+代码+操作标签+评分+趋势+置信度 | 评分 0-100 |
| 核心结论 | 一句话 | 没有则隐藏 |
| 市场快照 | 现价/涨跌幅/量比/换手+数据源声明 | 字段可用才展示 |
| 执行计划 | 理想/确认买入、止损、首个目标 | 只 4 个点位 |
| 技术参考 | 均线状态、MA5 乖离、支撑压力 | 不重复量能描述 |
| 催化与风险 | 正催化/风险警报 | **各最多 2 条** |
| 下一步观察 | 行动窗口+检查时间+观察条件 | 最多 2 条 |
| 持仓建议 | 只分未持仓/已持仓两态 | 长文留完整报告 |

大盘卡：市场信号灯（确定性评分，不二次评分）→ 指数（最多 4 个）→
市场宽度（涨跌家数/涨跌停/总成交额）→ 强弱板块（领涨领跌各 Top3）→
资金观察 → 明日策略（结论/仓位区间/失效条件）→ 风险提示（最多 2 条）。

### 共同的内容规律（我的归纳）

1. **单图信息密度高**：6-9 个模块，每模块 1 行结论+几个关键数字
2. **条数纪律严**：每类最多 2-3 条（催化 2、风险 2、板块 3）——
   逼着排序，不堆砌
3. **结论前置**：头部就是评分/信号/一句话，数据是支撑不是主角
4. **合规三件套**：风险提示条、数据截至、不构成投资建议
5. **诚实填充**：N/A 隐藏卡片、不二次评分、不补造字段——
   **和赤轨"避免黑箱"是同一条纪律，原样兼容**

## 五、赤轨的差距（对照后的事实）

| 维度 | 别人 | 赤轨现状（10-23 重设计后） |
|---|---|---|
| 渲染架构 | HTML 模板+无头浏览器 | canvas 手画（4 种版式，坐标手算） |
| 单图信息量 | 6-9 模块拼盘 | 1 个模块（排名列表/事件卡/大数字/梯队） |
| 组图叙事 | 封面+全景+结构+观点成套 | 单图 |
| 品牌/二维码 | env 配置化 | 只有"赤轨"水印 |
| 条数纪律 | 每类 2-3 条 | top 5/10/15 可调（可堆砌） |
| 条件渲染 | N/A 自动隐藏卡片 | 空数据显示占位文案（未做卡片级隐藏） |
| 诚实填充 | 不二次评分/不补造 | ✅ 已有（六关判决/证据引用传统） |

## 六、可抄清单（按性价比排，我的建议）

### 第一优先：渲染架构换 SVG 模板 + resvg（不引无头浏览器）

- 理由：daily_stock_analysis 的 HTML 路线要 chromium+字体（arm64 装包有
  akshare 前科之鉴，先探再定）；**SVG 声明式已经有 flex 布局子集
  （Satori）或直接手写 SVG+resvg 渲染**，纯 Node 无浏览器依赖，
  版式能力比 canvas 强一个量级，条件渲染就是模板里一个 if
- 落地：新建 `studio-card.ts`：StudioSpec → JSX/SVG 模板 → resvg → PNG。
  保留 canvas 实现做回退，双轨跑一段时间

### 第二优先：单图信息密度（模块化拼盘）

- 榜单图别只排名：加分布条（前 10 占比）、板块 mini 榜、涨停/跌停计数条
- 大盘图（stat 版式）：指数卡 + 涨跌分布 + 板块 top3/bottom3 + 资金观察一句
- 事件卡：标题 + 摘要 + 涉及票 + "接下来看什么"（AI 给一句）
- **条数纪律抄它的**：每类最多 2-3 条，逼排序不堆砌

### 第三优先：组图叙事（抖音/小红书成套）

- 一次生成**一组图**（不是一张）：封面大字报 → 全景 → 结构 → 观点/互动
- 封面模板：超大标题（AI 标题 10-18 字）+ 一个最炸的数字 + 高对比
- 抖音 9:16 / 小红书 3:4 / 公众号 16:9 各自成套（版式比例不同不是缩放）

### 第四优先：工程细节

- 品牌配置化：水印文案、二维码占位（用户自己贴）、账号名——写进 /settings
- 图片元数据清理（resvg 产物本来干净，记一笔）
- 「分享才生成」：批量预生成浪费，按需+缓存

### 明确不抄的

- 决策仪表盘的"评分/操作建议"形态——那是荐股形态，
  赤轨红线不碰（可以显示"市场温度/情绪"这类事实性指标，不显示"买入评分"）
- wkhtmltoimage 三引擎回退的复杂度——SVG 路线不需要
