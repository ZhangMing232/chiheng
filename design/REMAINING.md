### 12.2 流水轮转：**根因不是「文件会一直长」，是每分钟写同一句重复日志**

| 项 | 实测 |
|---|---|
| `gate-blocks.jsonl` | 1.64 MB / 6721 行 / 2026-10-08~11-06（29 天），244 B/行 |
| 增速 | 每个交易日稳定 **240 条**（≈ 57 KB/交易日，按 250 交易日算 ≈ **14 MB/年**；21 个交易日已攒 1.6 MB） |
| **去重后** | **唯一签名只有 621 条（9.2%）**，最重复的一条被写了 **249 次** |
| 今天 | 52 条里 51 条是同一句「交易日记录 17/60，样本还不够下结论」 |
| 读方 | **生产代码只写不读**——`readGateLogs()` / `hardBlocksOn()` 只有测试在调，页面没有消费方 |

**根因**（`scripts/record-journal.ts:509` 附近）：提示闸的 `buysPresentThisRun` 标志想
「样本不够只记一笔」，但记账进程**每分钟新起一个**，标志每次都是新的，于是每分钟
都写一条完全一样的 soft 记录。`gate-log.ts` 文件头注释还写着「写入频率低（只被拦时写）」，
已经和现实矛盾。

**两种去重口径都实测过，别混**（2026-11-06 交叉复核）：
- 按 `gate + reason` 算，6782 行里只有 **21 种话（0.31%）**——「交易日记录 4/60」986 次、
  「已连续亏损 3 个交易日，停止新开仓」529 次。这说明**日志的信息量极低**。
- 按 `tradingDate + gate + style + reason + candidates` 算，唯一签名 **621 条（9.16%）**——
  这是**按天去重后该保留的行数**，也是上表 9.2% 那个数的来源。
两个数字不矛盾：前者量「有几种话」，后者量「去重后剩几行」。**去重键必须带
`tradingDate`**，否则跨天的同一句会被合并，丢掉「哪天被拦」这个风控证据。

**我的建议：先去重，再谈轮转**。轮转 1.64 MB 的文件解决不了「每天 240 行噪声」；
把「同一交易日 + 同 style + 同 gate + 同 reason」写成一天一条（带 `count` 字段记次数），
文件一年只长几十 KB。去重之后：
- 若还要轮转：按月切 `gate-blocks-YYYY-MM.jsonl`，保留 12 个月 + 归档压缩，读取方按日期找文件。
- 但**当前没有生产读取方**，轮转的收益只是磁盘和备份体积；真正的价值是让这份
  「风控拦了什么」的证据变得可读（现在 90% 是噪声，没法复盘）。

**✅ 2026-11-06 拍板并已实施：只去重（方案①）**。用户复核后同意「只去重、轮转基本不需要」。
- 去重键 = `tradingDate + gate + style + reason + 候选股票 id 集合`，**不含买入价/分数**
  （价格每分钟在动，整块 candidates 塞进键会把同一天同一理由撑成 159 种，等于没去重）。
