# P2 对账评估：两份名单到底差在哪、差得有没有道理

> 2026-11-13，用户指令「一件一件来，先跑 P2 评估数据」。
> **纯只读评估**：不改 `record-journal.ts`、不写 `reviewed.json`、不动账本、不合一任何链。
> 复跑命令：`node --experimental-strip-types --import ./scripts/alias.mjs scripts/reconcile-p2.ts`
> 脚本：[`scripts/reconcile-p2.ts`](</Volumes/colorful/chiheng/scripts/reconcile-p2.ts>)，三分类直接调线上
> `reconcileDay` 纯函数，保证「分析口径」=「页面口径」。

---

## 0. 结论先行

**差得有道理，P2「两链合一」不该做。**

5 个交易日、100 只次信号、37 笔账本成交，重合只有 6 只（6.0%）。看起来像两页各说各的，
但把 31 笔「账本买了 /today 没提」逐笔拆开后，**没有一笔是丢单或算错**：

- 16 笔（52%）是**挑战者 / 深扫实验**——账本里带 `variant` / `deepScan` 标记，是策略进化管道
  故意开的独立实验田，`/today` 按定义不展示它们。
- 15 笔（48%）是**盘中新增扫描**——记账进程 09:30 起每约 4 分钟重扫一次 universe，
  09:26 竞价审核之后行情变了、新票进池，自然会买进 09:26 名单外。这不是不一致，是**时点不同**。
- 反向的「/today 说了没买」94 只次里，有 50 只次是 **short 腿（热点·题材补涨 = relay）**，
  该策略已在 `RETIRED_STYLES` 里明文「不再建仓、只结算历史仓」——**0 命中是设计使然**。

也就是说：**两份名单服务的不是同一个问题。** `/today` 是「09:26 竞价审核后的当日提案」，
账本是「一整天里所有真实成交（含实验田、含盘中新增）」。把它们合成一条链，等于
要求「提案」和「全天流水」逐笔相等，既不成立，也会毁掉两个本来各自有用的东西。

「/today ∩ 记账链」稳定在 9~10/20，正好是 `/today` 的**低估值 long 腿 10 只**——
两条链的候选池其实高度同源，差异主要来自「腿的取舍 + 盘中时点 + 实验田」。

### 11-09 / 11-12 两个极端，各自有解释

- **11-09 重合 0**：账本 16 笔里 8 笔是已淘汰策略（`rebound` / `trend` / `early`）与挑战者变体的
  历史结算，8 笔是记账链自己扫出来的银行股（工行 / 农行 / 中行 / 建行 / 杭州 / 上海 / 新华…），
  当天 `/today` 的 10 只低估值里一只都没进账本。同日记账链候选 26 只、`/today` 20 只，交集 10 只
  ——两链都从同一池子出发，只是选取口径不同。
- **11-12 重合 0，且账本 2 笔完全不在记账链候选里**：海尔智家、中国石油两笔都带
  `variant=value-stop10` + `deepScan`，**纯挑战者实验单**。当天常规 `value` 一套都没建仓。
  这是「实验田独立」最干净的一个样本。

## 3. 31 笔「账本独有」逐笔归因（互斥分类）

| 归因 | 笔数 | 占比 | 说明 |
|---|---:|---:|---|
| 挑战者 / 深扫实验 | 16 | 52% | 带 `variant` 或 `deepScan`，冠军-挑战者管道的独立实验田 |
| 盘中新增扫描（09:26 名单外） | 15 | 48% | 出现在 `signals.jsonl` 当天记录里，但不在 09:26 `reviewed.json` |
| **合计** | **31** | **100%** | **0 笔属于「算错 / 丢单 / 口径冒充」** |

逐日：`11-09` 实验 8 + 盘中 8；`11-10` 实验 2 + 盘中 1；`11-11` 实验 2 + 盘中 6；
`11-12` 实验 2；`11-13` 实验 2（卫星化学 / 南京银行，均为 `value-stop10` / `value-stop8` 深扫）。

**盘中扫描的证据**：`signals.jsonl` 每天 7~10 批时间戳（如 11-13 为
`09:30:11 / 09:34:10 / 09:37:10 / … / 10:10:13`），`record-journal.ts` 每次重跑
`watchList` + `takeBuys`。09:26 之后进池的票被买进，是这套机制的**预期行为**，
`PLAN-unify-daily-picks.md` §0 写的「两次扫描时点不同」在这里被逐笔证实了。

## 4. 落盘口径核查（P0 那条铁律再确认一次）

最新 `data/signals/reviewed.json` 落盘的信号字段里：
**`order` 0/20、`fill` 0/20**——理论成交（按当日日 K 事后重算）只由
`getSignalReviewed` 回给页面，**从不落盘**。所以：

- 页面上的「成交」是事后理论重算，账本里的 `entry` 是当时记下的真实成交，两者永不互相冒充；
- 本次评估只拿账本 `entry` 做「买没买」的判据，`fill` 一个字段都没用；
- 读不到的数据一律不补 0（脚本读不到账本或名单直接退出，不编数字）。

## 5. 对 P2 的裁决

`PLAN-unify-daily-picks.md` §4 设想的是「让 `reviewed.json` 成为账本唯一候选源，
`record-journal.ts` 不再自己扫 universe」。本轮数据给出的答案是**否**：

1. **会删掉实验田**：16/31 笔账本独有成交来自挑战者/深扫，09:26 名单里根本没有它们。
   合一 = 弃掉冠军-挑战者进化管道的真实样本，而这是 `STRATEGY-GEN2.md` 的核心资产。
2. **会删掉盘中**：15/31 笔来自 09:26 之后的行情变化。合一 = 全天只认早盘那一批，
   等于把「盘中新信号谁负责」这个计划里自己列为「现在没答案」的问题，用最粗暴的方式回答掉。
3. **会把已淘汰策略重新拉回来**：short 腿 50 只次是 `relay`，已被判决淘汰、只结算历史仓。
   让它进账本等于推翻二代换代判决书。
4. **没有可验证的收益**：两页现在都能如实标清「信号 N 只 / 成交 M 笔 / 重合 K 只」，
   用户看得懂差异；合一之后反而失去「提案 vs 全天流水」这个有用的对照。

**建议**：P2 从「待拍板」改为**「不做，保留双链 + 显式口径」**。
`PLAN-unify-daily-picks.md` §4 的四个前置问题（名额/T+1 与 skip 对齐、盘中新信号、
`reviewed.json` 只覆盖早盘、回测+双闸）现在有了实测答案：前三个都不是「待解决」，
而是「两链本来就分工不同」，强行对齐才是引入错误。

### 真正值得做的下一刀（比合一便宜得多）

| # | 动作 | 依据 |
|---|---|---|
| 1 | **把「账本独有」的三类归因做成页面标签**：挑战者实验 / 盘中新增 / 已淘汰策略结算 | 现在 `positions.tsx`「今日对照」只列票名与价格，用户仍要自己猜为什么没对上。31 笔已全部可自动归类 |
| 2 | **`/today` 的 short 腿标「观察 · 不建仓」** | `ACTIVE_STYLES=["value"]` 是代码事实，页面目前没说，用户会误以为 50 只次丢了单 |
| 3 | **给账本 `days[]` 无序加一条守门测试** | 见 §1 的 ⚠️，迟早有人写 `days[days.length-1]` 踩坑 |
| 4 | **每日自动落一份对账快照** | 现在历史 `/today` 名单只能从 23:30 备份里捞，脚本才凑出 5 天。落一份 `data/reconcile/<date>.json` 就能积累真实交易日样本 |
