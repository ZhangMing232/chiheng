# 页面装饰体系（PAGE-DECOR）

> 2026-10-23 立。之前 29 个页面长得一模一样（全是一堆 Panel 堆叠），
> 顶栏只有一行 11px 的「市场 / 复盘」小字。进任何页面都不知道自己在哪、
> 这页是干啥的。现在每个页面有自己的身份。

## 一、为什么要有装饰

不是"页面太素想加点东西"。是三个具体的坏处：

| 坏处 | 以前的样子 | 现在 |
|---|---|---|
| 认不出页面 | 29 页视觉完全一致，靠侧栏高亮才知道在哪 | 底纹色相 + 页头图标 + 职能句 |
| 不知道页面在讲什么 | 全靠翻内容自己总结 | 页头一句话说清这页的职责 |
| 不知道页面现在什么状态 | 要在内容里找 KPI | 页头状态药丸（真实数据） |

**装饰承载信息，不贴花纹。** 这是本设计的唯一标准——
一个装饰件如果只是好看、不能帮人更快知道"这是什么/现在什么状态"，就不做。

## 二、三层结构

```
L1 底纹（氛围）   ← 功能组色相，一眼知道在哪一组
L2 页头（身份）   ← 图标 + 页面名 + 一句话职能 + 状态药丸
L3 专属件（个性） ← 按页面核心概念给的独有装饰
```

### L1 底纹 · 功能组色相

**按功能组定，不按页面定**——同一组的页面底纹相同。

| 组 | 色相 | 页面 |
|---|---|---|
| 工作台 | 品牌赤 `#e63c4f` | 主控台 / 大管家 / 自媒体图文 |
| 市场 | 蓝 `#3d8bff` | 股市总览 / 每日复盘 / 资金流向 / 快讯 / 港美行情 |
| 策略因子 | 紫 `#8b7bd8` | 策略 / 因子发掘 / 回测 |
| 研究 | 琥珀 `#c9a869` | 个股研判 / 多空辩论 / 研报库 / 笔记 |
| 我的 | 绿 `#0bb97b` | 自选与持仓 / 提醒 / 设置 / 管理系统 |

**透明度刻意压到 7% / 4%**（第一版用 16% / 9%，渲染出来一看，五个组像
五套不同主题）。底纹是氛围，不是配色方案。深浅两套色值跟随
`html[data-theme]`。

> ⚠️ 涨绿跌红不参与。绿色在这里是"我的组"的氛围色，跟行情的"跌"是两回事，
> 但它们只出现在底纹和图标块（不承载数字），不会混淆。状态药丸也只用
> 中性/状态色（ok/warn/brand），**不用 up/down**。

### L2 页头 · 身份

```
[图标]  主控台   (今日信号 34 条)
        今天的账、信号和钱，一屏看完
────────────────────────────────────
实时 · 主力净流入前 3 合计 39.6 亿 · 记账 1 分钟前
```

- **页面名从导航表取**（`navHit`），不在装饰层写第二份——写两份必然对不上
- **职能句**来自配置表，写给用户看（"这页回答什么问题"），不是写给开发者看
- **状态药丸**：页面 loader 的真实数据。**没有数据就不显示药丸**，
  不拿 0 顶替"不知道"

### L3 专属件 · 个性

只有真正有得说的页面才有，不硬凑：

| 页面 | 专属件 | 显示的真实数据 |
|---|---|---|
| 主控台 | 实时 | 主力净流入前 3 合计 + 记账心跳 |
| 股市总览 | 走势 | 资金榜第一名 |
| 资金流向 | 流入/流出箭头 | — |
| 快讯 | 实时 | 利好/利空条数 |
| 因子发掘 | 六关判决 | 最强因子的 t 值 |
| 个股研判 | 证据链 | 阶段数 + 缺口数 + 换掉的数字数 |
| 多空辩论 | 多空对照 | 双方各自的状态（已出/拒答/失败） |
| 自媒体图文 | 风格预览 | — |

## 三、代码落点

| 文件 | 职责 |
|---|---|
| `src/lib/ui/page-decor.ts` | **配置表**：路径 → { 图标, 职能句, 色相, 装饰件种类 } + `decorFor()` |
| `src/components/page-decor.tsx` | **渲染件**：`DecorBackdrop` / `DecorHeader` / `DecorOrnament` |
| `src/components/screener/nav.tsx` | `Frame` 里注入三层（**一处注入，覆盖 41 个 Frame 用法**） |
| `src/lib/ui/page-decor.test.ts` | 10 条测试钉住配置表行为 |

**为什么做成配置表而不是散在页面文件里**：改一次装饰要动 29 个地方的话，
下次就没人愿意改装饰了。做成表就一处。

**为什么注入在 `Frame` 而不是各页面**：29 个页面原本长得一样，
装饰是全站性的。在 Frame 注入 = 一次改动，41 个页面全覆盖；
逐页加 = 改 29 个文件，且以后新页面还得记得加。

## 四、口径纪律（最重要的一条）

**装饰不许编数据。**

- 状态药丸的数字必须来自该页 loader 已经拉到的真实数据
- 算不出来就写 `null` → 页头少一个药丸（而不是显示 0）
- 「没跑过」和「跑了但没过」是两件事——因子页显示 `0 / 37` 而不是 `0`，
  意思完全不同
- 研判页的「悬空引用」条数要显式显示出来（warn 色调）——
  这正是"避免黑箱"红线所在，装饰层不能把它藏了

## 五、已接状态药丸的页面（11 个）

| 页面 | 药丸 | 数据来源 |
|---|---|---|
| 主控台 | 今日信号 N 条 | journal 的当日买卖笔数 |
| 股市总览 | 上涨 X / Y | getBreadth 计数 |
| 快讯 | N 条 | news 长度 |
| 因子发掘 | 过关 X / Y | batchSummary.passed / total |
| 策略追踪 | 在跟 N 只 | 未平仓笔数 |
| 自选与持仓 | 自选 N 只 | watchlist items |
| 提醒 | 未读 N 条 | 比 readMark 水位新的条数 |
| 笔记 | N 条 | notes 列表长度 |
| 研报库 | N 份 | rows 长度 |
| 管理系统 | N 人 | users 长度 |
| 个股研判 / 多空辩论 | 证据条数 / 悬空数 | report.chain |

没接的页面（回测、设置、港美、策略选股等）**页头照样有**（L1 + L2），
只是没有状态药丸——那些页面没有"今天什么状态"这个概念，硬凑一个反而是编。

## 六、待办

- ⬜ **L3 专属件还剩几个没做**：回测的「收益曲线缩略图」、快讯的「电报滚动动画」
- ⬜ **窄屏（手机）页头要重排**：现在图标 + 标题 + 药丸 + 职能句是横排，
  窄屏下职能句会被挤掉，需要单独一套竖排布局
- ⬜ **页头右侧的 actions 区**：组件支持了，但还没页面用上
- ⬜ 每个页面的职能句要定期复核——产品变了，句子得跟着改

## 七、页头标题的权威来源（2026-10-23 补）

**页头标题来自配置表的 `title` 字段，不来自侧栏导航表。**

原因：侧栏里没有 `/ai`、`/symbol`、`/membership`、`/strategies/positions` 这几个
入口。第一版页头标题用 `navHit(path)` 取，这四个页面拿到的是**空字符串**——
页头渲染成空的 `<h1></h1>`，底纹在但标题没了。端到端逐页检查才发现。

所以：
- `PageDecor.title` 是权威来源，侧栏 `navHit` 只管侧栏自己的高亮
- 两边各写各的会漂，但**页头比侧栏重要**（侧栏可以没有入口，页头不能没有标题）
- 测试钉住：每个配置必须有非空标题 + 那四个无侧栏入口的页面必须有标题

## 八、踩过的坑

- **底纹第一版太重**（16%/9%）：五个组看起来像五套主题。降到 7%/4%。
  **装饰的强度要靠实拍验证，不能凭想象调。**
- **组件文件里 re-export 常量会破坏 fast refresh**（eslint 报
  `react-refresh/only-export-components`）：类型和常量留在 `lib/ui/page-decor.ts`，
  组件文件只导组件。
- **装饰件的 `children` 传 null 时不能留空壳**：L3 没数据就整个不渲染。
- **页头标题不能依赖侧栏导航表**（见第七节）：4 个页面拿到空标题。
- **窄屏页头要竖排**：桌面端「图标 + 标题 + 药丸」横排，职能句在下面一行；
  窄屏下横排会把职能句挤掉——那一句是这一层唯一不能丢的信息
  （它回答"这页是干啥的"）。改成 flex-wrap + 职能句独占一行。
- **顺手修了个真 bug**：回测页的 `useMemo` 写在 `if (!picked) return ...` 之后，
  违反 Hook 调用顺序——`picked` 从 null 变成有值时渲染的 Hook 数量变了，
  React 直接抛「Rendered fewer hooks than expected」白屏。
  eslint 的 `rules-of-hooks` 早就报过，一直没人管。提到早退分支之前修掉。
